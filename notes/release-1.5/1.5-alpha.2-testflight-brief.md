# App Store alpha build for TestFlight (try it)

Rick, 2026-09-27 18:30 UTC: "let's _try_ and build an alpha app store bundle so that we can put it in testflight".

Mac work, for the M4. Source: the `v1.5-alpha.2` tag (58b5ce7). The store work (#106, sandbox, Full Disk Access flow) is on v1.5-alpha, and so are the store-only Patreon gate (08f2f73) and `ITSAppUsesNonExemptEncryption` (741f2f0).

## Steps (from macapp/README.md, "App Store configuration" and "Provisioning profiles")

1. `git fetch --tags && git checkout v1.5-alpha.2` in a clean worktree.
2. `aspect build //:macapp --bazel-flag=--config=appstore_release`. This signs with Apple Development and the development profiles, optimized; it rebuilds everything (`opt`), so it takes a while.
3. Optionally, launch that build once on the M4 (the development profile lists it) to confirm the sandboxed app starts.
4. Upload. The repo has no export path: the README's route is Xcode Organizer, which re-signs with Apple Distribution and the three Mac App Store profiles (`GarageMacAppConnect`, `GarageRAGAppStoreCLI`, `GarageRAGAppStoreMCP`). Organizer needs an `.xcarchive`, so wrap the Bazel `.app` in one by hand: `Garage.xcarchive/Products/Applications/Garage.app` plus an `Info.plist` with `ApplicationProperties` (`ApplicationPath`, `CFBundleIdentifier` me.rickmark.garage-rag, `CFBundleShortVersionString`, `CFBundleVersion`, `SigningIdentity`), `ArchiveVersion` 2, `CreationDate`, `Name`, `SchemeName`. Open it in Organizer, run **Validate App** first, then **Distribute App → App Store Connect → Upload** (TestFlight).
   - If the hand-made archive won't validate, the fallback is: re-sign by hand with Apple Distribution and the store profiles (inside-out, helpers and nested code first), `productbuild --sign "3rd Party Mac Developer Installer: …"`, then upload the .pkg with Transporter.
5. In App Store Connect: the build appears under TestFlight after processing. Rick answers the export compliance question (the app declares encryption: TLS to an https Ollama or LM Studio server) and adds testers.

## Watch for

- The build number must be higher than every build already uploaded (0.9 (66) is in review for 1.0). 376 is fine if that is what the store build carries; check `CFBundleVersion`.
- Validation may reject nested code the README flags: Postgres in `Resources/`, site-packages extensions, `Python.framework`, the two helper bundles. Record every error verbatim; each is a beta fix, not something to patch on the tag.
- Keychain prompts for the Apple Distribution key and the App Store Connect sign-in need Rick at the keys.
- Never kill xcodebuild/xctest by pattern; never point tests at the app's Postgres.
