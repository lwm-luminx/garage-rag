# Garage v1.5: recommendations before release

Reviewed 2026-09-24: the last week of work on main (60 commits, PRs #2 to #62, up to 076a6b7), open PR #62, issue #27, the GitHub releases, and today's project threads. Fable reviewed the repo on its own; where we both found something, it's marked "both". Tags: [checked] means I read it in the repo or on GitHub, [inferred] means it's reasoning from that evidence.

## Blockers (fix before archiving)

1. **The version still says 0.9.** `macapp/Sources/GarageApp/BUILD.bazel:37` sets `short_version_string = "0.9"`, but GitHub already has a v1.0 release (2026-09-21), and 0.9 (162) was last validated. App Store Connect won't accept a version that goes backwards, and Sparkle compares this string. Bump it to 1.5 with a new build number. `garage_python/pyproject.toml` (0.1.0) and the framework's `Info.plist` (1.0) are cosmetic. [checked, both]
2. **The Keychain read runs on the main thread, and the two builds can't share the item.** `PostgresService` is `@MainActor` (line 251). `postgresPassword()` (line 1046) calls `SecItemCopyMatching` (`GaragePostgresEndpoint.swift:45`) in the legacy file keychain with no access group. Each re-signed release, and every switch between the Developer ID and App Store builds, triggers an ACL prompt that freezes the window. When the prompt is denied, `PostgresService` throws "created by the other Garage build" (line 1060). v1.0 users who move to the store build hit exactly this, since their data migrates into the shared group folder. Fix: move the read off the main actor, and put the item in the data-protection keychain under the team's `keychain-access-groups` so both builds and the launchers share it. [checked; the cause of the freeze is inferred]
3. **The store build's `garage` and `garage-mcp` crash without PR #62.** On main they carry the `inherit` entitlement but are launched from Terminal or Claude Desktop, not by the app. PR #62 reports SIGTRAP (exit 133). Merge #62 once macOS CI passes, then check on the store build that the separately sandboxed launcher can still read the Keychain item. If it can't, stdio MCP is dead in the store build, and fixing #2 with an access group fixes this too. [checked, Fable]
4. **Sparkle can't deliver an update yet.** `docs/appcast.xml` is an empty channel. Generate a signed item with `//ext/sparkle:generate_appcast` as part of the release, or v1.0 Developer ID users never hear about 1.5. The public key is real. [checked, both]
5. **Mac-only checks are still open:** launching the store build on a fresh data folder; Organizer Validate App (install the GarageMacAppConnect profile); Postgres starting with AGE preloaded (`PostgresService.swift:430`: when `age.dylib` is present but fails to load, Postgres doesn't start at all); and a clean XCUITest run, which M4 is running now.

## Should fix (review or privacy risk)

6. **The launch-time fetch from garagerag.app isn't disclosed.** Commit 73a9356 calls `ModelCatalog.refresh()` at every launch (`AppState.swift:213`, URL `https://garagerag.app/.data/models.json`). The privacy policy says Garage doesn't transmit usage, and this request bypasses the egress guard by design. Either mention it in `docs/support/privacy-policy.md` and the App Privacy answers, or gate it behind the same consent as update checks. [checked, Fable]
7. **Info.plist asks for permissions the app never uses.** It declares Contacts, Calendars, Reminders, AppleEvents and SystemAdministration usage strings (`GarageApp/Info.plist:25-39`), but no matching entitlements. App Review asks where each one is used, so remove the unused ones. Also add `ITSAppUsesNonExemptEncryption` so each upload skips the export-compliance question. [checked]
8. **There is no `PrivacyInfo.xcprivacy`.** Swift code uses required-reason APIs (UserDefaults, file timestamps, disk space), and the bundled Postgres and Python use `stat` heavily. A manifest is cheap and avoids ITMS-91053 warnings turning into rejections. [checked that it's missing; how strictly macOS enforces it is inferred]
9. **Messages and Mail may not work in the sandboxed store build.** The site's hero promises them (`docs/index.md:24`), and the first-run flow points users at Full Disk Access. Full Disk Access doesn't lift the sandbox on `~/Library/Messages`; only a user-picked bookmark does. Try it on the store build, or say the feature is Developer ID only. An advertised feature that doesn't work draws a 2.1 rejection. [inferred, Fable]
10. **The v1.0 GitHub release still carries x86_64 assets**, while the site says Apple Silicon only. Leave them off the 1.5 release, and consider pulling them from v1.0. [checked]
11. **Justify `disable-library-validation`.** It's in the store app's entitlements, so have the Python-extension explanation ready for review. [checked, Fable]

- **Issue #27 has leftovers:** `BeginIngestSessionResponse` has no `kind`, `char_start`/`char_end` are never filled, the model catalog lives in three places, `.actrc` is a stray file, and `GarageCLIService` can drop its last output lines. The binary-quantization rerank and `expected_items` are done, so tick those off.
- **The duplicate merges are harmless.** #57 and #58 are empty merges; #51, #54 and #56 carried the work. [checked, Fable]
- **These look fine:** `GarageDataMigration` only renames, and the egress guard is intact (no network imports outside `net/egress.py`). [checked, Fable]
