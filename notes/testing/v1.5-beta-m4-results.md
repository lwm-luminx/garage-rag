## Failures

1. `ModelsUITests.testInferenceTabChoosesAModelAndFollowsDistillationAgain` (ModelsUITests.swift:112): the Inference tab does not list gpt-oss-20b.
2. `ModelsUITests.testDistillationTabMarksChatOnlyModels` (ModelsUITests.swift:149): the Distillation tab does not list gpt-oss-20b.
   - Cause: at launch the app fetches https://garagerag.app/.data/models.json (`ModelCatalog.refresh`, AppState.swift:307), saves it in the data folder and prefers it to the bundled copy. The site still serves main's catalog, which has no gpt-oss-20b. The beta's data/models/models.json lists it 6 times.
   - Fix options: skip `ModelCatalog.refresh()` when `--data-directory` is a UI-test folder, or deploy the beta catalog to the site. The failures go away by themselves once 1.5 reaches main and the site is redeployed.
3. `ModelUITests.testMenuBarAskAnswersFromTheCorpus` (ModelUITests.swift:340): the footnote reads "Searched once · gemma2-2b" instead of naming `uitest-deterministic`.
   - Likely cause (inferred from code, not reproduced separately): `GarageMCPService.environment()` (GarageMCPService.swift:799) passes only GARAGE_DATABASE_URL and the LM Studio token to the in-app MCP server. It does not pass `GARAGE_WORKING_DIRECTORY`, which the gRPC service does get (GarageGRPCService.swift:102). The MCP server's Python therefore never reads the data folder's garage.json and falls back to ~/.garage.json or the default facts.model (gemma2-2b).
   - The same gap likely affects real users: menu-bar Ask and the in-app MCP server would ignore the facts/inference model chosen in the app.
   - Fix: add `env[GarageXPCConfigurationKey.workingDirectory] = Paths.garageWorkingDirectory.path` in `GarageMCPService.environment()`, and have GarageMCPServerService apply it the way GarageXPCServiceDelegate.swift:63 does.
